# v0.4 Research Summary — Reverse Converter (imaging mzPeak → imzML)

**Confidence:** HIGH (load-bearing claims verified against vendored source).
(v0.3 research is in the sibling STACK/FEATURES/ARCHITECTURE/PITFALLS/SUMMARY.md files.)

## Stack — hand-roll the imzML write (zero new crates feasible)
- **No Rust imzML writer exists.** `vendor/mzdata/src/io/imzml/` has no writer; mzdata's mzML
  writer emits base64 *inline* (no `.ibd`/external-offset path). Alan Race's `imzml` v0.1.3 has
  `ImzMLWriter` but is stale (2022) + a new dep + forks the shared model → **documented fallback only**.
- **We hand-roll `.imzML` XML + `.ibd`.** Format is fully pinned by our own reader
  (`vendor/mzdata/src/io/imzml/reader.rs`):
  - `.ibd`: first **16 bytes = UUID raw bytes**, then arrays **concatenated raw little-endian** at
    recorded offsets. **NoCompression only** (reader errors otherwise) → write uncompressed.
  - binaryDataArray CV terms: `IMS:1000102` = byte offset into `.ibd`; `IMS:1000103` = array length
    (**element count**); `IMS:1000104` = external encoded length (**bytes** = `len * dtype.size_of()`).
    `<binary/>` stays empty.
  - `<fileContent>`: `IMS:1000080` UUID; checksum `IMS:1000091` SHA-1 / `IMS:1000090` MD5; mode
    `IMS:1000031` processed (our target).
  - Per-pixel coords: scan-event params `IMS:1000050/51/52` (1-based) in each `<spectrum><scanList><scan>`.
- **Zero-new-crates gate:** `md5` is already reachable (mzdata's mzML writer uses it); `sha1` may not
  be. **R0 dep audit decides** — prefer emitting MD5 (`IMS:1000090`, spec-legal) to stay zero-new-crates
  unless SHA-1 interop is required (then add the single `sha1` crate).

## Features (build by phase, suggested R0→R4 — continues v0.3 numbering at Phase 7)
- **R0/Phase 7** — read-spike + `cargo tree` dep audit (SHA-1 vs MD5 decision); confirm MzPeakReader
  yields coords + arrays on a real archive; call `load_all_spectrum_metadata()` once (avoid O(n²)).
- **R1 (crux)** — incremental `.ibd` writer: 16-byte UUID header, per-array raw LE append returning
  `(offset, element_len, encoded_len)`, streamed checksum. Pure byte math; unit-test offsets.
- **R2** — `.imzML` XML emit: Latin-1-safe; `<fileContent>` integrity terms; `<scanSettings>` from
  `metadata.imaging`; per-`<spectrum>` `<scanList>` IMS coords + two `<binaryDataArray>` (m/z, intensity).
- **R3** — streaming orchestration (read pixel → append `.ibd` → emit XML, bounded memory) + a `reverse`
  CLI subcommand with distinct exit codes.
- **R4** — `mzPeak → imzML → mzPeak` L1 roundtrip (reverse → existing `convert()` → existing
  `verify_streaming`) + full PXD001283-derived archive end-to-end.

## Architecture
New `src/reverse/{mod,source,imzml_writer,convert}.rs` mirroring `src/write/`'s seam. Reuse:
- `src/read` coordinate/array extraction patterns; `src/integrity` UUID/checksum (preflight catches
  UUID/checksum mismatches "for free").
- MzPeakReader: `new` / `len` / `get_spectrum` / `get_spectrum_arrays` / `get_spectrum_metadata` /
  `load_all_spectrum_metadata` / `file_index().metadata["imaging"]`. Coordinate read reuses
  `src/verify/verify.rs::build_index_coords` (`get_param_by_curie(IMS:1000050…)`).
- `src/verify` verbatim for the L1 fidelity bar (reverse → forward → verify_streaming).
- `reverse` subcommand in `src/cli.rs` mirroring `classify_exit`.

## Pitfalls → phase
- `.ibd` offset/length arithmetic (element-count vs byte-count) → R1 (unit-test).
- UUID raw-16-bytes vs dashed-text; checksum range/algorithm; compressed `.ibd` → R1 (preflight guards).
- ISO-8859-1 vs UTF-8 XML (the v0.3 Latin-1 landmine) → R2.
- XML well-formedness + correct IMS CV terms; processed per-spectrum binaryDataArray wiring → R2.
- mzdata must re-read our output → gated free by preflight + forward `convert()` in R4.
- MzPeakReader O(n²) without metadata cache → R0/R3.

## Open questions for requirements
1. **SHA-1 vs MD5 checksum** — decide after R0 dep audit; prefer reusing present `md5` (zero new crates).
2. Copy source `<sourceFileList>` provenance into reverse `.imzML`? (nicety, not L1.)
3. Third-party (non-v0.3) archive variability — best-effort; keep read-side extraction accession/transform-driven, not array-name-gated.
