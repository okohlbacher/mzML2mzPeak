<objective>
Make the v0.4 reverse imzML `<scanSettings>` emission spec-faithful for units, absolute offsets,
and the z grid count — closing FID-01, FID-02, FID-03.

Three additive, source-faithful changes, all routed through the existing `write_scan_settings_to`
emitter and proven against the Phase-9 `mzdata::ImzMLReader` oracle:

1. **FID-01 (µm units):** attach `unitCvRef="UO" unitAccession="UO:0000017" unitName="micrometer"`
   to the existing `IMS:1000044/45/46/47` cvParams (max-dimension + pixel-size). Pure emitter change.
2. **FID-02 (absolute offsets):** add an OPTIONAL `absolute_offset_um {x,y}` (`AxisPair<i64>`) to
   `ImagingMetadata` + `schema/imaging.json` + the spec-doc snippet, and emit `IMS:1000053` (x) /
   `IMS:1000054` (y) with the µm unit WHEN that field is present (omit when absent). The
   forward-population of this field from imzML is DEFERRED to v0.6+ (recorded in
   NEXT-ROADMAP-DRAFT.md "Deferred during v0.5 execution") — so the round-trip this phase delivers
   is: the reverse emitter faithfully re-emits offsets that a source mzPeak index carries.
3. **FID-03 (z carry-through):** `ImagingMetadata.pixel_count.z` already exists (Phase 12); ensure it
   flows through the reverse path and is not dropped. There is NO standard IMS accession for a z grid
   COUNT (IMS:1000042=x count, 1000043=y count only) — so FID-03 is carry-through + a documented note,
   NOT a fabricated z-count accession (the per-pixel z coordinate IMS:1000052 is separate and already
   handled in `write_spectrum`).

Purpose: faithful reverse emission so an mzPeak imaging archive round-trips its run-level geometry
units/offsets/z back into valid imzML the wider MS-imaging ecosystem can re-read.
Output: updated emitter + extended `ImagingMetadata`/`imaging.json`/spec-doc + green mzdata-oracle tests.
</objective>
