# Milestone v0.5 — Index enrichment & optical-image import — Audit

## Verdict: PASSED

All 13 milestone requirements satisfied, all 4 phases verified, all 14 cross-phase integration
points wired, the end-to-end forward-enrichment + TIFF-import flow proven by the e2e suite. No
critical gaps. Three non-blocking tech-debt items recorded (one vendored-fork upstream issue + two
v0.6-deferred forward-geometry items, all documented and accepted in scope).

## Definition of Done (from ROADMAP)

> Enrich the forward (imzML→mzPeak) index.json with the imaging flag, derived per-dimension MS
> pixel counts, and global MS1 m/z bounds (written last); import one or more optical TIFF images as
> separate archive members with a full-extent affine into the MS pixel grid recorded in index.json;
> plus a small reverse-emit fidelity pass. Every change fed back into the spec doc + schema.

**Met.** Forward `convert(reader, out, --image …)` writes `metadata.imaging` last with `is_imaging`,
`pixel_count{x,y[,z]}` + `pixel_count_source`, `mz_range` (MS1), and `images[]` (each with
archive_path/source_name/dims/sha256/size/affine/role); `MzPeakReader` reads it all back.
