<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| argv → clap | User-supplied paths/flags parsed at the binary boundary |
| imzML/.ibd → preflight/reader | Untrusted file content; integrity-gated before any parse |
| user output path → File::create | Path used verbatim; no shell-out, no interpretation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-6-exit | Spoofing / poor failure signaling | classify_exit | mitigate | Distinct non-zero ExitCode per failure class (integrity=2, unsupported=3, coord=4, verify-fail=5, generic=1) via anyhow downcast; clear messaging is the security-relevant CLI-04 contract. |
| T-6-integrity | Tampering | convert/dry-run input gate | mitigate | Reuse `preflight()` (UUID + checksum hard-fail) before any read; the CLI never bypasses it; a bad .ibd maps to exit 2 + actionable message. |
| T-6-path | Tampering / EoP | output PathBuf → File::create | mitigate | Path passed as `PathBuf` straight to std file APIs; no shell-out, no string interpolation into a shell; clap parses argv directly. |
| T-6-panic | DoS / poor UX | run() error surface | mitigate | Library returns typed errors; cli.rs wraps with anyhow context and `main` prints `{e:#}` — no raw panic/unwrap on fallible paths reaches the user. |
| T-6-SC | Tampering | npm/pip/cargo installs | mitigate | No new crate added in this plan (indicatif promoted in Wave 1); zero `[ASSUMED]`/`[SUS]` packages → no install checkpoint required. |
</threat_model>
