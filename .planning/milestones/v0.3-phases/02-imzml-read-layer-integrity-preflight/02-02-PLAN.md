<objective>
Build the converter-owned integrity preflight (IN-07) that runs BEFORE any streaming and
hard-fails on a bad .ibd. mzdata only `warn!`s on UUID mismatch and does not check the
checksum at all (PITFALLS.md Pitfall 3), so the converter must own this gate. The
preflight generalizes the proven approach from `src/bin/verify_ibd.rs` (RFC-4122
first-16-byte UUID compare + whole-file digest) along four review-mandated axes:

1. BOUNDED header parse — stream the .imzML header with a chunked reader and STOP at the
   first `<spectrumList`; never `fs::read` the whole 56MB file.
2. PINNED Rust digest crates — replace the `shasum`/`md5` shell-out with `sha1`, `md-5`,
   `sha2`, streaming the .ibd in fixed-size chunks (never loading 815MB into memory).
3. DECLARED ibd file name — prefer `IMS:1000070` to locate the .ibd; fall back to the
   sibling stem only when absent; hard-fail if the resolved path does not exist.
4. REAL non-zero exit proof — a `src/bin/preflight.rs` binary maps Err to a non-zero
   ExitCode, and an integration test SPAWNS it (std::process::Command) to assert a
   non-zero exit and a clear stderr message for each failure class. A mere `Err` return is
   not sufficient evidence for ROADMAP criterion 3.

Scope: UNCOMPRESSED .ibd only (the vendored reader supports NoCompression only — see
reader.rs ~line 991 — and IN-04/ROADMAP are scoped accordingly). Preflight itself does not
decode arrays, so compression does not affect it, but the wording stays aligned.

Purpose: refuse to vouch for a mismatched, corrupt, or missing .ibd with a clear error and
a non-zero exit — the converter must never silently read the wrong binary.

Output: an `integrity` module with a `header` parser and a `preflight` entry point, a
`preflight` binary, pinned digest dependencies, deliberately-corrupted fixtures, and
integration tests proving the hard-fail behavior both as typed Err and as a spawned
non-zero exit.
</objective>

<imzml_header_facts>
From 01-FINDINGS.md and verify_ibd.rs (empirically confirmed):
- IMS:1000080 "universally unique identifier" — the imzML-declared .ibd UUID (textual, e.g.
  {C7822330-F1A8-4D11-AD30-504B30B33722}). Compared RFC-4122 / big-endian byte-for-byte to
  the .ibd first 16 bytes (this is the REQUIRED path; the .NET mixed-endian reading is a
  diagnostic only — see verify_ibd.rs).
- IMS:1000091 "ibd SHA-1" — declared whole-file SHA-1 (HR2MSI: F8C24417...; continuous
  fixture: a5be532d...). IMS:1000090 = MD5, IMS:1000092 = SHA-256 are the other possible
  declarations; handle whichever ONE the imzML contains.
- IMS:1000070 "ibd file" / external binary uri — the declared .ibd file name when present;
  prefer it over the stem-derived sibling path.
- These params live in the imzML <fileDescription> header, BEFORE the <spectrumList> — a
  bounded byte-level Latin-1 scan only needs the head of the file. The HR2MSI .imzML is
  ~940k lines; a whole-file read is forbidden.
- The checksum digest itself spans the WHOLE .ibd (byte 0..EOF, UUID bytes included).
</imzml_header_facts>
