<objective>
Wire the CLI so direction is inferred from the input extension (`.imzML`/`.imzml` → forward,
unchanged v0.3 path; `.mzpeak` → reverse), with an explicit `--reverse` override and an `-o`
stem that derives `OUT.imzML` + `OUT.ibd`, and extend `classify_exit` with a `ReverseError` arm
mapping every variant to a distinct non-zero exit code.

Purpose: Delivers RCLI-01 — the user-facing reverse invocation and its actionable, distinctly-coded
error surface — while keeping the shipped forward invocation byte-compatible (no `convert` verb,
no positional break, so the v0.3 acceptance harness is untouched).
Output: `src/cli.rs` extended (struct fields, `run()` dispatch, `derive_reverse_paths` helper,
`classify_reverse_error` helper, unit tests). No new crates; `anyhow`/`indicatif` stay confined here.
</objective>

| T-10-PATH | Tampering | `-o` stem path handling | accept | `derive_reverse_paths` uses `std::path` only; the path is passed verbatim to `File::create` (no shell, no interpolation, no `..` expansion by us); the user owns their output path — low risk for a local CLI (RESEARCH §Security Domain) |
