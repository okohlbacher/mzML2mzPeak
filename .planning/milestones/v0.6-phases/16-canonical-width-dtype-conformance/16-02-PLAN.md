<objective>
Redefine the L1 fidelity contract from "bit-for-bit at the source stored width (no widen/narrow)" to "value-equal at canonical mzPeak width (`mz=f64`, `intensity=f32`)", and update the verify comparators to compare at canonical width — so source-vs-output dtype divergence is NO LONGER a mismatch. Also update the spec doc's L1 Conformance paragraph so the contract is consistent across the three places it is stated (code + spec).

After Plan 01 the forward data facet ALWAYS emits f64 m/z + f32 intensity. The current verifier decodes the OUTPUT at the SOURCE width and treats a width divergence as a mismatch (`compare_axis` reports F32/F64 divergence; `compare_profile_masked` decodes the output at the source element type via the `run_merge!` macro). That logic must flip: decode the output at CANONICAL width and coerce the source to canonical for the comparison.

Purpose: the comparator is the second half of the L1 redefinition (DECISION 2). Without it, every f32-m/z source would falsely fail verify against the now-f64 output. PXD001283 (already f64 m/z + f32 intensity) must still pass unchanged.
Output: an L1 verify path that passes value-equal-at-canonical-width and stops penalizing the intended widening/narrowing, with the spec doc's Conformance paragraph aligned to the new contract.
</objective>
