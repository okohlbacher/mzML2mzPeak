<objective>
Relax the reverse read path's roundtrip bar from "dtype-identical to the original source" to "value-equal at canonical width". After Plan 01 the forward profile data facet always stores f64 m/z + f32 intensity, so a `mzPeak → imzML → mzPeak` roundtrip that started from an f32-m/z source will now read back f64 m/z. The reverse path must accept this canonical-width data as correct (value-equal) WITHOUT attempting to recover the original source dtype.

The reverse read already decodes each axis at its STORED dtype via `decode_axis` (Float32/Float64) and REJECTS any non-float dtype with `UnsupportedDtype` (the integrity guard). That stays. What changes is the EXPECTATION/contract: the stored canonical width IS the reference; there is no "original source dtype" to recover, and the roundtrip is judged value-equal, not dtype-identical.

Purpose: the reverse half of the L1 redefinition (DECISION 2). Without it, the reverse-roundtrip test bar would still implicitly demand the pre-cast source width.
Output: a reverse read path whose documented contract is value-equal-at-canonical-width, with the non-float reject guard intact.
</objective>
