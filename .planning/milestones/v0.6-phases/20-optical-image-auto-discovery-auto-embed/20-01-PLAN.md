<objective>
Build the LIBRARY core for optical-image auto-discovery: a quick-xml parser that extracts every
`IMS:1006008` "optical image location" (+ its descriptive sibling attrs) from the source imzML, a
path-resolution helper that turns each location into a concrete file under the `.imzML` directory
tree (rejecting path-escape), and the generalization of the v0.5 embed helpers in `image.rs` from
TIFF-only to any image format. NO `convert.rs` wiring in this plan — that is Plan 02.

Purpose: OPT-01 is "parse `IMS:1006008`, resolve relative to the `.imzML`, auto-embed any format."
This plan delivers the three reusable, unit-testable pieces; Plan 02 threads them into the terminal
embed seam. Isolating the parser + resolver + format generalization here keeps the `convert.rs`
wiring thin and makes the multimodal (≥2 images), path-escape, and non-TIFF edge cases testable
without building an archive (mirrors how `geometry.rs` and `image.rs` were split in Phase 15/18).

Output: `src/schema/optical.rs` (new module), updated `src/schema/mod.rs` re-exports, and a
generalized `src/write/image.rs` (magic-byte TIFF detection + format-agnostic `build_image_entry`).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imzML `IMS:1006008` value → filesystem path | The optical-image location string is attacker-influenced (a malicious/crafted imzML can put any path here). It crosses from untrusted XML into a `File::open`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Tampering / Elevation | resolve_optical_location (path-escape) | mitigate | Reject `..` segments / paths resolving outside the `.imzML` dir tree with a TYPED error (reusing the v0.5 convert.rs path-separator guard intent). A rejected escape is surfaced as an error to the caller, NOT silently resolved. |
| T-20-02 | Information Disclosure | resolve_optical_location reading arbitrary files | mitigate | A `file://`/absolute/relative location that climbs out of the imzML tree is rejected before any `File::open`, so a crafted imzML cannot read `/etc/passwd` via IMS:1006008. |
| T-20-03 | Denial of Service | non-TIFF verbatim embed (whole-file copy) | accept (mitigated downstream) | image.rs only computes is_tiff (4 bytes) + media_type here; the verbatim byte stream + bounded sha256 happen in Plan 02 via the existing 64KiB streaming `add_file_from_read`/`sha256_and_size` — never a whole-file load. |
</threat_model>
