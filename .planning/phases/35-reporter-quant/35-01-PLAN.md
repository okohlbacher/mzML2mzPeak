<objective>
Establish the reporter-ion-quantitation foundation for Phase 35 (QUANT-01..02): prove — through THIS
repo's OWN reader — whether a per-MS2 reporter-intensity auxiliary array tagged with a `channel_id`
column survives a write→finish→read-back round-trip, and add the `--reporter-quant` CLI flag (OFF by
default) with forward-mzML-only rejection guards.

The read-back SPIKE is the load-bearing risk in this phase (design R2-M3): third-party read-back of
aux arrays is a KNOWN blocker (R null-fills struct columns; the Python binding is name-gated). This
plan deliberately does NOT depend on third-party readers — it tests `mzpeak_prototyping::MzPeakReader`
(the vendored reader this project already uses for `--verify` and roundtrip). A BLOCKING decision gate
after the spike chooses the emit contract for Plan 35-02: aux-array (if read-back works) or a documented
sidecar map (if it does not).

Purpose: De-risk the aux-array contract before any extraction/emit code is written, and wire the gating
flag so the no-flag path stays provably byte-identical (first-to-cut, lightest-priority facet — design
§8 Phase 35, RATIFIED-D).
Output: `src/write/reporter_quant.rs` (contract + spike test + fallback shape), the `--reporter-quant`
flag, and a recorded decision-gate outcome that Plan 35-02 keys its emit path off.
</objective>

  This is the own-reader read-back path the spike exercises.

From src/write/mzml.rs (the writer path the spectra flow through):
- `convert_mzml(input, output, opts, sdrf: Option<&Path>)` streams `reader.iter()` mzdata
  `MultiLayerSpectrum` entries through `writer.write_spectrum(&entry)`. Extra arrays beyond the
  canonical m/z+intensity spill to `spectrum.auxiliary_arrays` (DAT-01 — see src/write/spectrum.rs

  auxiliary_arrays"). The finalize seam is `writer.finish_parquet()? → zip.add_index_metadata(..) →
  zip.finish()?` — typed members / index KV are inserted between.

From mzdata (the array carrier on a spectrum):
- a spectrum's `arrays: Option<BinaryArrayMap>` accepts extra `DataArray`s; a non-canonical name uses
  `ArrayType::NonStandardDataArray(name)` (the writer maps unknown arrays to auxiliary_arrays).
