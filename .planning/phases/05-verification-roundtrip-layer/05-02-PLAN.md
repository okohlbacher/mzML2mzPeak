<objective>
Build the verification core: the ion-image reconstruction (`ion_image.rs`, VER-04) and the
orchestrator (`verify.rs`) that wires count → coordinate-pair-map → per-axis numeric compare →
ion-image sanity into a `VerificationReport`.

Per RESEARCH Pitfall 5, the orchestrator is SPLIT: a public path-based
`verify_roundtrip(source_path, output_path, level)` (for the Phase-6 CLI / PXD001283 gate,
which opens an `ImagingReader` over a real `.imzML`/`.ibd`) AND a source-spectra-driven core
`verify_against_source(source: &[ImagingSpectrum], output_path, level)` reachable by tests that
have no `.ibd`. `verify_roundtrip` materializes the source via `ImagingReader` then delegates to
the core.

Purpose: This is the correctness engine for VER-01..VER-04. It branches on the SOURCE
representation (profile → data facet, centroid → peaks facet with the source as the L1
reference per CONTEXT Area 2), pairs by coordinate key (never by sequential index), and builds
the spec-§5.1 `M[row=y][col=x]` top-left TIC grid with a presence mask for sparse grids.

Output: `src/verify/ion_image.rs`, `src/verify/verify.rs`, and the added re-exports in
`src/verify/mod.rs`. Unit-tested in-module for the pieces reachable without a live archive.
</objective>
