## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `--sdrf` file → parser | The user-named TSV is untrusted input crossing into the model |
| SDRF cell text → SourceCurie::parse | Cell-controlled `AC=` token shape-validated, never resolved/fetched |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Denial of Service | parse_sdrf on a huge/ragged TSV | mitigate | csv reads record-by-record (no whole-file slurp into one String); ragged rows tolerated by flexible(true), an unreadable/empty file → typed SdrfError early, not unbounded growth |
| T-31-02 | Tampering | basename matching in match_rows | mitigate | compare PATH-STRIPPED basenames/stems only (directory components discarded), so a crafted `comment[data file]` path cannot widen the match to an unrelated file |
| T-31-03 | Information disclosure | SourceCurie shape-only validation | accept | passthrough by design (Cornerstone A): no ontology fetch, no network; a malformed AC= degrades to extra-preserved free text, never a crash |
| T-31-SC | Tampering | `csv` crate install | mitigate | `csv` is the only new dep — verify legitimacy via crates.io/crates/csv (image-rs-adjacent maintainer rust-lang/csv-rs, multi-million downloads) BEFORE relying on it; pinned with `=`; pure-Rust leaf, no network build script |
</threat_model>
