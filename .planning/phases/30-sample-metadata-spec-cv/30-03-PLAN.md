<objective>
Define the KV-JSON contracts the v0.8 sample-metadata stream emits into mzPeak's index.json `metadata`
map: `metadata.study` (global study context — accession / title / back-ref) and the reused
`metadata.sample_list` (id / name / parameters), each with its matching `schema/*.json` (draft-07,
additionalProperties:false) — SMSPEC-03. This is the third "place" of the three-places rule for these
contracts (the cv.rs / cv-requests place is Plan 30-02; the spec write-up place is Plan 30-04).

Purpose: per the v0.7 extension contract, file-level facts ride mzPeak's open `FileIndex.metadata`
`HashMap<String, serde_json::Value>` written via `add_index_metadata(key, val)`. v0.8 adds two keys —
`study` and `sample_list`. This plan DEFINES their Rust types + JSON schemas so Phase 32's emitter
(SM-05) writes a contract that already exists rather than inventing shape at emit time. The
`metadata.study` block is also the home for the interim `run_sample_binding` provenance shadow Phase 32
writes until Phase 30b's upstream `ms_run.sample_ref` merges — so reserve that optional slot now.

Output: `src/schema/study.rs` (the `StudyMetadata`/study-context type), `schema/study.json`,
`schema/sample_list.json`, and the `src/schema/mod.rs` re-exports for both the new `study` module and the
`source_curie` module from Plan 30-01. Mirror `src/schema/transform.rs` + `schema/transform.json` exactly.

This plan is CONTRACT-DEFINITION ONLY — it defines types + schemas. No facet emits; the emitter lands in
Phase 32 (SM-05). The `sample_list` shape is REUSED from v0.6 `sample.json` (no new construct,
RATIFIED-E) — this plan confirms/authors the schema, it does not redesign the sample shape.
</objective>
