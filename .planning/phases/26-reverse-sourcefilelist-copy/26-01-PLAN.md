<objective>
Wire `file_description.source_files[]` (forward-recorded by Phase 19) back into the reverse `.imzML`
`<sourceFileList>` so original imzML/.ibd provenance (id/name/location + UUID + checksum CURIEs)
survives the `mzPeak -> imzML` round-trip (RSRC-01).

Today `imzml_writer.rs::write_header_to` (line ~356) emits a HARDCODED single
`<sourceFileList count="1"><sourceFile id="sf_reverse" ...>` describing OUR output lineage only — the
inline comment "OUR output lineage only (NOT the upstream's — deferred per CONTEXT)" marks exactly the
deferral Phase 26 resolves. This plan replaces that hardcode with a `<sourceFileList>` reconstructed
from the read-back `source_files[]`, threaded in from the reverse `convert` orchestrator.

Purpose: restore vendor/source provenance on the reverse path — the last RSRC gap.
Output: a `write_source_file_list_to` emit helper, `write_header_to` taking a `source_files` slice,
`convert`/`run_pipeline` reading it off the reader once, and an XRT round-trip assertion.

This is PURE WIRING of existing values: `source_files[]` is already a spec File-Level Metadata member
(extension-contract §3.3), already written forward (Phase 19), already deserialized on read into
`reader.file_description().source_files` by the vendored reader (`reader/metadata.rs:410-414`). No new
archive member, no new JSON key, no new dependency, no pinned-stack change.
</objective>

Read-back surface (the reverse path already opens this reader in convert.rs):
  `MzPeakReader` implements `mzdata::meta::MSDataFileMetadata` (vendor reader.rs:287), so:
    `reader.file_description() -> &mzdata::meta::FileDescription`
  `mzdata::meta::FileDescription` (mzdata 0.64) fields:
    `pub contents: ParamList`          // the existing SPA-04 contents mapping (UUID/checksum/mode)
    `pub source_files: Vec<SourceFile>` // <-- what Phase 19 pushes; what we re-emit
  `mzdata::meta::SourceFile` fields:
    `pub name: String`                 // e.g. "Example_Processed.imzML" / "Example_Processed.ibd"
    `pub location: String`             // e.g. "file:///path/to/dir"  (may be "file://")
    `pub id: String`                   // "imzml" / "ibd" (Phase 19 push_source_files)
    `pub file_format: Option<Param>`   // MassSpectrometerFileFormatTerm-defined, if present
    `pub id_format: Option<Param>`     // NativeSpectrumIdentifierFormatTerm-defined, if present
    `pub params: ParamList`            // the .ibd entry's IMS:1000080 UUID + IMS:1000090/91/92 checksum

  IMPORTANT — `SourceFile::params()` (the ParamDescribed accessor, via impl_param_described!) returns
  ONLY `self.params`; it does NOT include `file_format`/`id_format`. To re-emit FAITHFULLY the helper
  must emit `params` cvParams PLUS the `file_format` and `id_format` params when each is `Some`.

  Param accessors (mzdata::prelude::ParamDescribed / ParamValue):
    `param.curie() -> Option<CURIE>`   // CURIE has `.controlled_vocabulary` + Display "IMS:1000080"
    `param.name -> String`             // term name, e.g. "universally unique identifier"
    `param.value.to_string() -> String`// the value (e.g. the UUID string / checksum hex)
    A param's cvRef is its CURIE's controlled vocabulary (e.g. "IMS" / "MS" / "UO"); a param with NO
    curie() (user param) is emitted as a `<userParam name="..." value="..."/>` OR skipped — see action.

Emit seam (imzml_writer.rs free helpers — reuse, do NOT reinvent escaping):
  `fn emit_raw(sink: &mut impl Write, s: &str) -> Result<(), ReverseError>`     // static scaffolding
  `fn emit_escaped(sink: &mut impl Write, value: &str) -> Result<(), ReverseError>` // dynamic values
  `fn emit_cv_param(sink, cv_ref, accession, name, value) -> Result<(), ReverseError>` // valued cvParam
  `fn emit_cv_param_flag(sink, cv_ref, accession, name) -> Result<(), ReverseError>`   // presence-only

Existing header signature to extend (associated fn):
  `pub fn write_header_to(sink: &mut impl Write, uuid: Uuid, ibd_md5_hex: &str, count: u64,
      imaging: Option<&ImagingMetadata>, samples: &[(String, RecoveredOptical)]) -> Result<(), ReverseError>`
  Current hardcoded block lives between the IMS:1000031 "processed" flag and `</fileDescription>`
  (imzml_writer.rs ~lines 355-363). `Self::new(...)` calls `write_header_to(.., &[], <samples>)`.

Orchestrator call site (convert.rs::run_pipeline ~line 207):
  `ImzmlWriter::write_header_to(&mut out, uuid, &md5, count, imaging.as_ref(), &samples)?;`
  `imaging` is already read off the reader earlier; `reader` is in scope (it is the `archive` reader).
