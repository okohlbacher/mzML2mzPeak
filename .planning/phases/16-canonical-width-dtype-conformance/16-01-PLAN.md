<objective>
Make the forward profile `spectra_data` facet ALWAYS emit canonical mzPeak dtypes — `mz=f64`, `intensity=f32` — regardless of the source imzML binary array widths, and record/warn on any narrowing.

m/z `f32→f64` is lossless widening (exact, value-equal). intensity `f64→f32` is lossy narrowing (the only real information loss). On any narrowing the converter records a per-axis provenance note in metadata (a `DataProcessing`/`ProcessingMethod` entry on the channel `write_run_metadata` already uses) AND emits a CLI WARNING naming the axis and source→target dtype. Lossless widening emits neither.

Purpose: resolve the binary-array dtype collision (HUPO-PSI #11) by conforming the converter to mzPeak's fixed data-facet schema. This is the cast half of the LEAD phase — the contract redefinition (Plan 02) and reverse bar (Plan 03) build on the settled canonical output here.
Output: a forward write path that produces canonical f64 m/z + f32 intensity data-facet columns from any source dtype, with narrowing recorded + warned.
</objective>
