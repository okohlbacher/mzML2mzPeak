Opening the reader (open_path is a TRAIT method on MZFileReader, NOT an inherent ctor):

- `impl SpectrumSource<...> for ImzMLReaderType` (reader.rs:1210) — gives the standard mzdata `Iterator<Item = MultiLayerSpectrum>` (reader.rs ~1194) and `get_spectrum_by_index`. Iterate for a streaming, bounded-memory count.
- `pub imzml_metadata: ImzMLFileMetadata` field on the reader (reader.rs:528).

`ImzMLFileMetadata` struct (reader.rs lines 52-59):
  - `pub uuid: Option<Uuid>`
  - `pub data_mode: Option<IbdDataMode>`
  - `pub ibd_checksum: Option<String>`
  - `pub ibd_checksum_type: Option<String>`   // "MD5" | "SHA1" | "SHA256"
  - `pub ibd_file_name: Option<String>`        // OPTIONAL — not part of the GO gate
`pub enum IbdDataMode { Continuous, Processed, Unknown }` (reader.rs:43-49 — note the THIRD `Unknown` variant; match it).

Per-spectrum coordinate access (coords are scan params on a `ScanEvent`, which is
`ParamDescribed`):
- `Acquisition.scans: Vec<ScanEvent>` is public (scan_properties.rs:294); prefer the
  panic-free accessor `acquisition().first_scan() -> Option<&ScanEvent>` (scan_properties.rs:304)
  over `scans[0]` indexing.
- `ScanEvent` implements `ParamDescribed` (scan_properties.rs:819 `impl_param_described_deferred!(... ScanEvent)`),
  giving `get_param_by_curie(&CURIE) -> Option<&Param>` (params.rs:2196).
- Value → integer: `Param` is `ParamValue`; use `param.to_i64() -> Result<i64, ParamValueParseError>` (params.rs:97). Treat an Err the same as a missing coordinate (coord_missing).
- DO NOT claim coordinate access is "verified in vendor tests.rs" — the vendored 0.63.3
  tests only exercise `is_imzml` and the `ImzMLReader<File,File>` type. The real evidence
  is the fixture XML: each `<spectrum>` carries a `<scan>` with
  `<cvParam accession="IMS:1000050" name="position x" value="..."/>` and IMS:1000051
  (verified by inspecting Example_Continuous.imzML), and `ScanEvent: ParamDescribed`.

m/z point count — the CORRECT accessor chain (the naive `spec.raw_arrays().mzs().len()`
does NOT compile):
- `SpectrumLike::raw_arrays(&self) -> Option<&BinaryArrayMap>` (spectrum_types.rs:175/645).
- `BinaryArrayMap::mzs(&self) -> Result<Cow<[f64]>, ArrayRetrievalError>` (bindata/map.rs:203)
  — returns a `Result`, NOT a bare `Cow`. (The bare-`Cow` `mzs()` at spectrum_types.rs:404
  is on `RawSpectrum`, a different type, and panics on missing array — do not use it.)
- Correct chain for a length, where missing arrays must surface as failure:
  `let n_mz = spec.raw_arrays().and_then(|a| a.mzs().ok()).map(|m| m.len());`
  → `Some(n)` = materialized array of length n; `None` = a FAILURE for this pixel (count it
  as mz_missing, do NOT print n_mz=0 as if success).
