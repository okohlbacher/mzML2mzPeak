- CRITICAL: The automated verification can pass without proving continuous coordinates. It greps globally for one `idx=0 x=...` line and `pixels=34840`, both satisfied by the processed HR2MSI run alone. Fix: verify scoped output, e.g. assert a `=== CONTINUOUS` block contains `idx=0 x=... y=... n_mz=...` and `pixels=9`.
- CRITICAL: Continuous m/z “shared vs materialized” is not proven by `n_mz` lengths alone. The fixture repeats the m/z external offset `16` for every spectrum; vendored reader code seeks/reads into each spectrum, but the spike plan only observes length. Fix: print for continuous head sample both `n_mz` and the m/z array external offset, or document source-backed conclusion: repeated offset in XML plus `load_ibd_arrays()` per-spectrum read means full array is materialized per returned spectrum.
- MAJOR: The plan’s API note/action conflicts on m/z accessor. `spec.raw_arrays().mzs().len()` is not real: `raw_arrays()` returns `Option<&BinaryArrayMap>` and `mzs()` returns `Result<Cow<[f64]>, _>`. Fix: use `spec.raw_arrays().and_then(|a| a.mzs().ok()).map(|m| m.len())` or fail explicitly on missing arrays.
- MAJOR: The plan claims coordinate usage is “verified in vendor tests.rs”; vendored 0.63.3 tests only cover `is_imzml` and the `ImzMLReader<File, File>` type. Fix: remove that claim; cite actual source: scan params are in the fixture XML under `<scan>`, and `ScanEvent` implements `ParamDescribed`.
- MAJOR: `ImzMLReader::open_path` is a trait method from `MZFileReader`, not an inherent constructor. It is real, but only if the trait is in scope. Fix: require `use mzdata::prelude::{MZFileReader, SpectrumLike, ParamDescribed, ParamValue};` and `use mzdata::curie;`.
- MAJOR: The spike only requires the local HR2MSI file for processed mode, while copied `Example_Processed` is not exercised. That leaves the committed processed fixture unproven. Fix: either run both processed subjects, or remove `Example_Processed` from claimed proof artifacts.
- MAJOR: `ibd_file_name` is likely absent in the checked fixtures and local file. The plan says print `ABSENT`, which is fine, but “run metadata reachable” must not imply every metadata field is present. Fix: acceptance should require `data_mode`, `uuid`, `ibd_checksum`, `ibd_checksum_type`; make `ibd_file_name` optional with fallback note.
- MAJOR: `scans[0]` is guarded for zero scans, but missing x/y params are not specified as hard failure. A `None` printed as `ABSENT` or skipped could still produce misleading `pixels=`. Fix: count `coord_ok`, `coord_missing`, `no_scan`; GO only if `coord_ok == pixels` for both modes.
- MAJOR: Acceptance does not require nonzero m/z lengths. A broken array path returning `n_mz=0` would match `n_mz=[0-9]+`. Fix: require `n_mz>0` for sampled spectra and document failures separately.
- MINOR: Fixture copying is sound: `/tmp/mzdata/test/data/imaging` exists with all four files and `.ibd` siblings. `.gitignore` ignores `data/*.ibd`, not `tests/fixtures/...`. Fix: verify all four `git check-ignore` results, not just one continuous `.ibd`.
- MINOR: `open_path` derives `.ibd`/`.IBD`; copied sibling names match. Fix: include a `test -f "${imzml%.imzML}.ibd"` style check for both fixtures.
- MINOR: The plan’s `pixels=34840` grep is valid only for HR2MSI. Continuous fixture has `spectrumList count="9"`. Fix: assert `pixels=34840` under processed and `pixels=9` under continuous.
