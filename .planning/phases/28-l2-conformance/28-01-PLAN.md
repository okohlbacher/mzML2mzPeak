<objective>
Add the L2 **transform record** as a file-level `metadata.transform` JSON block, emitted by the
plain-mzML write path (`convert_mzml`) whenever a lossy (numpress-linear) m/z transform was
applied. The block records the transform CURIE, the L2 tolerance (m/z ≤1e-7, intensity ≤1e-3,
from `ToleranceContract::L2` — imported, never re-encoded), and the data-processing step ref, so
a numpress-written file **honestly declares L2**. The transform CURIE (`MS:1002312`, numpress
linear) gets a SINGLE source in `cv.rs`, reused by the file-level block AND consistent with the
array-index `transform` field the vendored writer already stamps (no drift).

Purpose: L2-01 requires the applied transform be recorded in BOTH the Array Index `transform`
field AND a file-level `metadata` JSON conformance/transform block (28-CONTEXT.md, extension
contract §3.8). The vendored writer ALREADY populates the per-column array-index `transform`
CURIE for numpress columns (`buffer_descriptors.rs` `BufferTransform::NumpressLinear.curie()` →
`MS:1002312`). This plan adds the MISSING half: the file-level block, single-sourced and schema-governed.

Output: `schema/transform.json`, `src/schema/transform.rs` (the `TransformRecord` type +
`numpress_linear_transform()` constructor), a `numpress_linear_curie()` accessor in `cv.rs`, the
`add_index_metadata("transform", ...)` insert in `convert_mzml`, and the spec write-up edit
(three-places rule).
</objective>
