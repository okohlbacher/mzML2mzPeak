<objective>
Wire the Plan-01 parser/resolver/embed-generalization into `convert.rs`'s terminal image seam:
auto-discover `IMS:1006008` images from the source imzML (no `--image` needed), embed each (TIFF →
first-IFD dims, non-TIFF → verbatim bytes + media_type by extension), map the descriptive CV attrs
onto the `ImageEntry`, SOFT-FAIL on a missing/unreadable auto-discovered image (warn + continue),
keep explicit `--image` HARD-fail, and coexist+dedup the two sources into one deterministically
ordered `images[]`.

Purpose: OPT-02 (descriptive-attr mapping), OPT-03 (soft-fail asymmetry), OPT-04 (coexist + dedup +
deterministic ordering). This is the behavioral heart of the phase — it must NOT weaken the v0.5
`--image` strict contract, must embed once when both sources name the same file, and must never let a
path-traversal attempt be silently swallowed by soft-fail.

Output: a generalized image-embed loop in `convert.rs` that takes BOTH the `--image` list (strict)
and the auto-discovered refs (soft), with a strict/soft mode flag on the embed helper.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imzML `IMS:1006008` value → `File::open` + ZIP member | The auto-discovered location is attacker-influenced; convert_with resolves + opens it. The archive member name is ALWAYS the deterministic ordinal (never the attacker string). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Tampering / Elevation | resolve_optical_location in convert_with | mitigate | A path-escape rejection is logged as a DISTINCT warning (traversal/rejected reason) and the ref is skipped — soft-fail does NOT silently mask a traversal attempt. |
| T-20-04 | Spoofing | archive member naming | mitigate | The ZIP member is `images/image_{ordinal:04}.<ext>` where <ext> is derived from the source path's own extension (lowercased, sanitized to a known set / "bin"); the attacker-controlled basename never becomes the archive path (T-15-06 carry-forward). |
| T-20-05 | Denial of Service | verbatim non-TIFF embed | mitigate | Bytes streamed via add_file_from_read (64KiB) + sha256_and_size second bounded pass — never a whole-file load, regardless of image size. |
| T-20-06 | Tampering | soft-fail masking a real defect | accept | A missing/unreadable AUTO image is intentionally non-fatal (OPT-03, auxiliary data); every skip is warned so it is observable. --image stays hard-fail so a user-named file's absence is never softened. |
</threat_model>
