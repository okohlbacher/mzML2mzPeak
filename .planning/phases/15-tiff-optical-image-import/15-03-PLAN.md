<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI `--image <path>` (user input) → File::open + derived source_name | Untrusted path + filename cross into the converter |
| user-supplied TIFF bytes → ZIP member | Bytes copied verbatim into the archive; only dimensions are parsed |
| derived source_name → emitted index.json | A crafted basename must not inject a path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-06 | Tampering / EoP | path traversal via crafted image filename | mitigate | Archive name is the fixed ordinal `images/image_NNNN.tiff` (never attacker-controlled); `source_name` is `path.file_name()` basename-only and REJECTED if it still contains `/` or `\` (Pitfall 4 / V5). |
| T-15-07 | Tampering | un-registered ZIP member → FileIndex drift | mitigate | Add via `add_file_from_read(.., Some(name), None)` (registers an `Other` FileEntry atomically) — never raw `zip::ZipWriter` writes (anti-pattern). |
| T-15-08 | Tampering | silent image corruption in the archive | mitigate | Per-image SHA-256 + size recorded in `images[]` (Plan 02 `sha256_and_size`); validator WARNs on mismatch (IMG-03, auxiliary). |
| T-15-09 | DoS | huge/malformed TIFF | mitigate | `read_tiff_dimensions` reads IFD only; `add_file_from_read` streams 64 KiB chunks; `sha256_and_size` streams — no full-file load anywhere. |
| T-15-10 | Tampering | reverse path silently running image logic | mitigate | `run_reverse` rejects `--image` (forward-only) with a clear error; no reverse image code added. |
</threat_model>
