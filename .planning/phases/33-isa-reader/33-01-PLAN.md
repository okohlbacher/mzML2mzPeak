<objective>
Add a SECOND reader front-end that fills the SAME unified `SampleMetadataDoc` model — this time
from **ISA-Tab** (`i_Investigation.txt` / `s_*.txt` / `a_*.txt`), the MetaboLights block-structured
tab format. The ISA-Tab grammar differs from SDRF in two ways: (1) it is block-structured (the
investigation file is a sequence of named section blocks, each a tab-delimited key→values row set),
and (2) CV linkage is **out-of-band** — a value column is followed by `Term Source REF` +
`Term Accession Number` columns, instead of SDRF's inline `NT=…;AC=…`. This plan delivers the
ISA-Tab parse front-end only (no CLI, no embed seam — those are Plan 33-03). Reuse the Phase-31
`SampleMetadataDoc`/`Sample`/`Assay`/`TypedValue`/`VerbatimBundle`/`Diagnostic` model and the
Phase-30 `SourceCurie` verbatim CURIE type — do NOT recreate them.

Purpose: prove a native MetaboLights ISA bundle ingests into the one keystone model, so the
Phase-31/32 emit + projection plumbing (reused in Plan 33-03) carries ISA losslessly.
Output: `src/isa/mod.rs`, `src/isa/tab.rs`, and the `pub mod isa` wiring in `src/lib.rs`.
</objective>

| Boundary | Description |
|----------|-------------|
| ISA-Tab file bytes → parser | untrusted file content (cells contain arbitrary text, URLs, embedded separators) crosses here |
| paired Term Accession Number cell → SourceCurie::parse | untrusted accession string shape-validated, never fetched |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33a-01 | Tampering | ISA cell with embedded `;`/`=`/`"` | mitigate | csv reader `quoting(false)` + no trim/case-fold — cells survive byte-for-byte; pairing keys on column POSITION, not cell content |
| T-33a-02 | Information disclosure | malformed/URL Term Accession Number | mitigate | `SourceCurie::parse` is shape-only (never fetches); Err → preserved in `extra` (lossless), no network call |
