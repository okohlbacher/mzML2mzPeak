<objective>
Add the THIRD parse front-end (after SDRF cells and ISA-Tab blocks): an **ISA-JSON** `serde::Deserialize`
layer plus `@id`-reference resolution, feeding the SAME `SampleMetadataDoc`. ISA-JSON is the same ISA
object model serialized as nested JSON (`investigation → studies[] → {materials.sources,
materials.samples, processSequence, assays[]}`); material and process nodes carry stable `@id` strings
and reference each other by `@id`, so the reader must build an id→node map and resolve references
(not just deserialize). No local ISA-JSON fixture exists, so this plan SYNTHESIZES a minimal one.
Pure-Rust: `serde_json` is already a dependency (CLAUDE.md) — add NO new crate.

Purpose: complete the "three front-ends, one model" design (§4.2) so ISA studies that ship as JSON
(MetaboLights' serialized form) ingest identically to ISA-Tab.
Output: `src/isa/json.rs`, the `parse_isa_json` re-export, and `tests/fixtures/isa/minimal.json`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ISA-JSON bytes → serde_json | untrusted nested JSON crosses here (arbitrary nesting, arbitrary @id strings) |
| @id reference → node map lookup | a reference may point at a non-existent or cyclic node |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33b-01 | Denial of service | deeply nested / huge ISA-JSON | accept | serde_json is the pinned, hardened parser; convert-time inputs are operator-supplied sibling files (same trust as the mzML) |
| T-33b-02 | Tampering | dangling / cyclic `@id` reference | mitigate | resolution is a HashMap lookup returning Option; miss → Diagnostic, never panic; no recursion without a visited-set guard |
| T-33b-03 | Information disclosure | URL/non-CURIE termAccession | mitigate | `SourceCurie::parse` shape-only (no fetch); Err → lossless passthrough, identical to the ISA-Tab reader |
| T-33-SC | Tampering | npm/pip/cargo installs | mitigate | NO new dependency (serde_json already pinned per CLAUDE.md); slopcheck N/A |
</threat_model>
