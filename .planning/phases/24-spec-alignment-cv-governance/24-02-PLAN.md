<!-- The exact spec mechanisms the contract must cite, extracted from /tmp/spec-index.md
     (rewritten HUPO-PSI/mzPeak-specification index.md, nominal v0.9). -->

1. File-Level Metadata: "Some metadata is descriptive of the entire run … stored as JSON in the
   Parquet key-value metadata of the `metadata` data kind files." (index.md "File-Level Metadata").
   The spectra_metadata.parquet file-level JSON already carries file_description,
   instrument_configuration_list, data_processing_method_list, software_list, sample_list,
   scan_settings_list (TODO), run. → This is where cv_list, channel_list, geometry live.

2. Column Name Inflection: column name = `${CV_CODE}_${CV_ACCESSION}_${CLEANED_NAME}`; cleaned name
   regex `/[^a-zA-Z0-9_\\-]+/`; "m/z"→"mz"; unit suffix `_unit_${UNIT_CV_CODE}_${UNIT_CV_ACCESSION}`.
   The recommendation table names only MS/UO short names — IMS columns inflect by the same rule.

3. The `parameters` list: a per-facet list column (`value{integer|float|string|boolean}`, `accession`,
   `name`, `unit`) — the cvParam/userParam carrier. Uncontrolled params omit `accession`.

4. Adding a new Data Kind: (1) pick a lower-case name fitting index JSON, (2) pick a layout, (3) describe
   relationships to Entity Types (prefer 1:1/1:N; create a new Entity Type if none fits). `data_kind`
   controlled values: `data arrays`, `peaks`, `metadata`, `proprietary`, `other` (loose, grow over time).

5. Adding a new Entity Type: controlled values `spectrum`, `chromatogram`, `wavelength spectrum`,
   `other`; anything else treated as `other`. (Section is a TODO stub in the spec — note that gap.)

6. mzpeak_index.json `files[]` entries are `{name, entity_type, data_kind}`; `other`-typed members are
   how the verbatim SDRF / embedded TIFF ride along (already used by v0.5 optical TIFF embed).
</spec_mechanisms>
