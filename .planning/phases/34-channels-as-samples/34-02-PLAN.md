<objective>
Wire the Plan-01 channel core into the existing `project_sample_list` projection so that an isobaric
SDRF run produces LABELED `sample_list` entries — each channel's entry carries: a sample-label cvParam
(MS:1002602 reagent child, e.g. TMT126), a reporter-ion m/z param (when resolved), a channel-role param,
and a tag_modification (Unimod) param parsed from the row's `comment[modification parameters]`. Non-
isobaric runs are untouched (parameters: []). Prove it with a read-back acceptance test on a TMT fixture,
a no-`--sdrf` byte-identical control, and an explicit "no channel_list" assertion.

Purpose: closes CHAN-01..03 — channels modeled as labeled samples, NO new construct. The run→sample
binding shadow ALREADY lists all N channel sample-ids (each channel is a distinct `source name` in the
fixtures, deduped by the existing `build_run_sample_binding`), so the binding needs no change.

Output: extended `src/sdrf/project.rs`; new `tests/sdrf_channels.rs`. **`src/write/mzml.rs` and
`src/cli.rs` are NOT touched** — `project_sample_list(&doc)` is already the seam call (mzml.rs:473) and
channels are auto-detected from the SDRF (no new flag). This keeps Phase 34 parallel-safe with Phase 33.
</objective>
