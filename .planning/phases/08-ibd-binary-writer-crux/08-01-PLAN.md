<objective>
Produce the milestone's highest-risk artifact: a byte-exact `.ibd` binary sidecar whose
offset/length arithmetic the imzML reader will accept on re-read. This phase writes ONLY the
`.ibd` container (`IbdWriter`) and returns, per binary array, the exact
`(offset, element_count, encoded_len)` triple that Phase 9's XML emitter turns into the
external-data CV refs `IMS:1000102/103/104`. No XML, no `reverse` CLI, no roundtrip.

Purpose: The element-count-vs-byte-count cursor arithmetic is the single biggest correctness
risk of the whole reverse converter. Isolating it behind a tiny pure-arithmetic seam and
exhaustively unit-testing it against HAND-COMPUTED expected triples (mixed f32/f64 +
multi-spectrum) is what de-risks the milestone.

Output: `src/reverse/ibd.rs` (`IbdWriter` + `ArrayRef`), an extended `ReverseError`, a
`pub(crate)` `compute_digest` reachable from `src/reverse`, and the unit-test battery proving
byte-exactness, offset accumulation, the IMS:1000103=element-count contract, checksum
whole-file coverage, UUID round-trip, and the empty-array edge case.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-memory `NumArray` → on-disk `.ibd` bytes | The writer serializes already-validated `NumArray` records (dtype constrained to {F32,F64} by Phase 7) plus a caller-supplied output path into raw bytes. No untrusted parse happens here; the risk is mis-sized/mis-offset output that a later reader will over-read. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-103 | Tampering (data integrity) | `IbdWriter::append` IMS:1000103 semantic | mitigate | Emit ELEMENT count (`arr.len()`) into the count field, not bytes; reader multiplies by dtype.size_of() (reader.rs:993-994). Unit-tested `count_is_elements_encoded_is_bytes` for f32 AND f64 (Task 2). |
| T-08-UUID | Tampering / Spoofing (file identity) | `IbdWriter::new` header | mitigate | Write `uuid.as_bytes()` (16 raw RFC-4122 bytes) — never dashed text, never a .NET byte-swap. Round-trip test `uuid_header_roundtrips` asserts `Uuid::from_bytes(file[0..16]) == writer.uuid()` (Task 3). |
| T-08-CKSUM | Tampering (integrity verification) | `IbdWriter::finish` checksum range | mitigate | Hash byte 0..EOF (header included) via the shared `compute_digest`; `checksum_covers_whole_file` asserts equality with an independent whole-file MD5 and that a header-excluded digest differs (Task 3). |
| T-08-OF | Denial of Service (integer overflow) | `count * dtype_size` arithmetic | mitigate | Compute `encoded_len` and the cursor in `u64`; realistic data (<=~10^4 elems/array x 34,840 arrays) is far below u64::MAX, so no wraparound. No `usize` arithmetic on the byte sizes. |
| T-08-TRUNC | Tampering (silent corruption) | unflushed BufWriter / OS-position drift | mitigate | `flush()`+`drop` the BufWriter before hashing (Pitfall 4); offsets come from an explicit in-struct `u64` cursor, never `stream_position()` (Pitfall 5). Byte-exact 68-byte assertion (Task 2) catches truncation. |
| T-08-MEM | Denial of Service (unbounded memory) | streaming constraint | mitigate | `BufWriter<File>` sink + per-element `to_le_bytes` writes + 64KiB-chunked digest; the whole `.ibd` is never buffered in a Vec (RCLI-02 carry-forward for 34,840 spectra). |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase — every crate (uuid via mzdata, md-5, sha2, mzdata) is already pinned and verified via `cargo tree` (08-RESEARCH Package Legitimacy Audit). No slopcheck required. |
</threat_model>
