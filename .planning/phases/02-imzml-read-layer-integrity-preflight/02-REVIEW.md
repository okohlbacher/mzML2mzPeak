# Phase 2 — Start-of-Phase Adversarial Review (Codex/gpt-5.5)

**Date:** 2026-06-03 · **Verdict (round 1):** EXECUTE-READY: no

- CRITICAL — 02-01/02-03 lock record arrays to `mz: Vec<f64>` and `intensity: Vec<f32>` from `BinaryArrayMap::{mzs,intensities}`, but those accessors coerce, not preserve dtype. `to_f32()` downcasts `Float64` intensity; `to_f64()` widens `Float32` m/z. HR2MSI specifically declares m/z `MS:1000523` 64-bit and intensity `MS:1000521` 32-bit, so current HR2MSI intensity as `f32` is fine; the generic contract is still lossy and violates Phase 2 “32/64-bit float” plus VER-03 L1 bit-for-bit. Fix: record source dtype per axis and either expose raw decoded bytes + dtype, or typed enum arrays (`F32(Vec<f32>)|F64(Vec<f64>)`); only offer mzdata-coerced accessors as convenience, not canonical data.
- CRITICAL — 02-03 acceptance can pass while L1 is already impossible for continuous m/z: fixture declares m/z `MS:1000521` 32-bit, but plan emits `Vec<f64>`. Numeric value may be exact, but source dtype/bytes are not preserved. Fix same as above; tests must assert declared dtype is carried and raw decoded bytes round-trip.
- MAJOR — 02-02 claims bounded header parsing but starts with `std::fs::read` of the whole `.imzML`; the HR2MSI file is ~940k lines. Fix: stream bytes with `BufReader::read_until(b'\n')` or chunked scanner and stop at `<spectrumList`.
- MAJOR — 02-02 says “non-zero exit” but tests mostly assert `Err`; the example/binary is optional. This does not prove roadmap criterion 3. Fix: add a real validate/preflight bin or integration test spawning a command and asserting non-zero for UUID mismatch, checksum mismatch, and missing `.ibd`.
- MAJOR — 02-02 checksum implementation delegates to platform tools (`md5`, `shasum`), which is non-portable and makes checksum coverage brittle. Fix: add pinned Rust digest crates or explicitly test tool availability per checksum type; verify MD5/SHA1/SHA256 fixture snippets.
- MAJOR — 02-02 derives sidecar path from stem and ignores declared `IMS:1000070 ibd file name`. mzdata also derives sibling path, but converter-owned preflight should validate the declared sidecar when present. Fix: parse `IMS:1000070`; prefer it, fallback to sibling only if absent.
- MAJOR — 02-03 “processed_streams_when_ibd_present” can silently skip the only 34,840-spectrum full streaming proof on default test runs. That leaves IN-01/IN-08 not checkable in CI/fresh clone. Fix: mark it as an explicit required local acceptance command, or add a committed small processed fixture plus a separate required local full-file gate.
- MAJOR — 02-03 only greps for `.collect::<Vec`; `collect()` without turbofish, `Vec::from_iter`, `read_to_end`, or retaining every `ImagingSpectrum` would evade it. Fix: acceptance should include a memory-bounded run or instrumentation, not grep-only proof.
- MAJOR — 02-03 `ReadError::Decode{index, source}` is under-specified; mzdata iterator `read_next()` swallows parser errors and returns `None`, so malformed offset/length may become early EOF rather than `Err`. Fix: inspect mzdata error exposure or wrap `read_into` directly so decode/IO failures are surfaced.
- MAJOR — 02-01 proposes `uuid::Uuid` but the project has no direct `uuid` dependency and mzdata does not re-export `Uuid` from `io::imzml`. Fix: either add pinned `uuid` dependency intentionally, or store UUID as normalized `String`.
- MINOR — 02-01 says `cargo test --lib record::`, but integration with module path may not select tests as intended. Fix: name concrete tests or use `cargo test --lib`.
- MINOR — 02-02 typo “BYTE-FOR-FOR-FOR”; harmless but sloppy in an executable plan. Fix text.
- MINOR — 02-03 checks `ms_level >= 1`, but continuous fixture has `MS:1000511 value="0"`. Fix: carry unchanged; test exact fixture value or only assert presence/unchanged, not `>=1`.
- MINOR — 02-03 coverage for zlib is asserted in roadmap, but imzML reader currently rejects non-`NoCompression` IBD arrays. Fix: either scope Phase 2 to uncompressed imzML IBD and change roadmap, or add a compressed fixture and implementation path.
EXECUTE-READY: no — dtype-preservation contract, non-zero preflight proof, bounded parser, and full streaming proof are blockers
